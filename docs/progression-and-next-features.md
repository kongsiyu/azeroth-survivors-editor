# 后续配置项探索与英雄难度通关（v1.7.0）

## 本轮完成

地图面板新增每职业、每地图的 **最高英雄通关等级 I–V**，同时保留普通通关开关。支持批量应用于已通关地图、恢复导入值、修改摘要、统一加密导出和重新导入。

- 选择英雄等级会同时标记该图普通通关。
- 将英雄等级设为“尚无英雄通关”，保留普通通关。
- 取消普通通关会同时清除该图英雄记录。
- 批量功能只处理当前职业已经普通通关的已知地图；可先标记全部普通通关，再批量选择英雄等级。
- 尚未由游戏初始化进度的职业继续保持禁用，避免制造游戏无法识别的职业进度。
- 原存档中的未知地图、未知未来英雄等级和未修改记录保持原样；重复或无法识别的英雄记录会禁止对应职业编辑。

## 存储证据与行为

本轮在先前下载的官方网页客户端中确认：

```text
beat|8|elwynn,sm
hbeat|8|elwynn:1,sm:3
```

上例表示职业 8 的普通通关包含艾尔文森林和血色修道院，最高英雄通关分别为 I 与 III。`hbeat` 的第三列用逗号分隔地图条目，每个条目以冒号分隔地图 ID 和等级。

静态解析依据：客户端 WASM 的存档读取函数（代码段内函数序号 11）先以逗号拆分 `hbeat` 条目，再以冒号拆分地图与等级；读取等级后使用上限 5。客户端难度名称也包含 Normal、Heroic I–V。二进制 SHA-256：`d3db2a367b8abc9a5e6fb8a4786edf99767e31ec156cff5b9c414aae16d476f7`，版本字符串 `0.128.0`，取自 2026-10-29 网页客户端。此处描述该份客户端，不代表所有历史或未来版本。

官方客户端文字说明：本职业普通通关后可进入该图英雄难度；任意职业的英雄 N 通关会为账号开放下一英雄等级，并提高该职业相关装备的升星上限。编辑器保存最高值，无需为低级英雄逐条重复创建记录。

**通关历史与出战设置分开。** 本轮仅修改 `beat/hbeat` 和必要的旧版 `unlock`，保留 `pick` 中的当前出战设置、`open`、角色、装备、成就、印记等其他记录。

## 推荐游戏测试

使用游戏最新导出存档，保留原始备份。先选择一个已经普通通关的地图，例如法师血色修道院：

1. 在编辑器选择法师，将血色修道院“最高英雄通关难度”设为 **英雄 III**。
2. 统一导出，并导入游戏。
3. 检查该图英雄进度是否达到 III、英雄 IV 是否可选择，以及对应装备的升星上限。
4. 重开游戏或完成一局后再次检查是否保留。

浏览器层已经验证 `hbeat|8|sm:3` 的实际导出和重导入；游戏内生效与持久化需要本轮人工确认。不要用只调整出战难度的结果代替通关历史测试。

## 其他缺失配置项：重新核实后的结论

| 配置项 | 字段与当前认识 | 下一步 |
| --- | --- | --- |
| 装备实际星级 | `stars` 为独立记录；英雄通关提高的是可升星上限，实际星级另存 | 优先补全 ID→星级格式、装备所属地图与上限公式，再增加逐件/按套升级；当前分析工具保留原始星级字段，避免猜测分隔符 |
| 武器光效 | `glow|职业|数值`，不是成就点或可消费货币；本例为 `glow|8|1894` | 提取光效 ID 对照表及成就/星级条件，做独立外观选择 |
| 伙伴外观 | `pets` 保存第一个、第二个拾取伙伴的外观 ID，本例为 `macaw,squirrel`；不是宠物收藏集合 | 提取外观目录和解锁成就，再做两槽选择；第二伙伴是否出现还由永久强化决定 |
| 种族解锁 | `races` 为账号级解锁；官方文字确认种族购买消耗成就点，强化重置不会退回 | 补齐种族费用和可用职业规则后开放编辑；本轮先识别其未知费用，暂停这类存档的精确余额目标调整，避免把费用视为零 |
| 战袍 | `tabard` 为已购买战袍，费用也影响成就点；部分成就战袍不使用该购买记录 | 提取费用和 ID 表，补齐余额计算后再做购买/外观编辑 |
| 装备穿戴 | `equip|职业|槽位:ID,...`；槽位采用游戏实际槽位，而非收藏表的顺序 | 校验职业、武器/副手组合与已拥有装备，做穿戴页 |
| 幻化与外观 | `look` 和 `hero` 分别涉及装备外观及角色外观档案；部分外观 ID 不在装备收藏目录 | 按实际槽位与模型目录实现，避免用收藏装备 ID 直接覆盖 |
| 图鉴最高稀有度 | `seen` 的数值表示该条目曾见过的最高稀有度，0–4 不是简单的发现开关 | 可优先实现已有条目的稀有度编辑；完整解锁需要图鉴目录 |
| 天赋构筑 | `spec` 已有三槽数据，当前只同步激活构筑 | 增加切换/复制/分别编辑，并同步修改现有的专精一致性保护 |
| 生命周期统计 | `stat` 含击杀、金币统计、胜利等；并非所有数值都是可消费余额 | 独立高级统计页，说明与成就重算的联系 |
| 装备保底 | `pity` 为装备 ID 对应计数，具体上限与随机购买规则仍需核实 | 用一次购买前后的存档对比验证，再开放写入 |
| 组队通关 | 客户端还有 `coopbeat` | 确认组队导出样例及结构后单独处理，不混入单人 `hbeat` |
| 当前出战难度 | `pick` 的尾字段在不同版本中发生过变化，旧实现曾是四项百分比设置，当前样例为单个数值 | 按版本确认编码后另做出战设置；本轮英雄通关编辑不改动该字段 |

建议后续顺序：**实际星级与升星上限 → 图鉴稀有度 → 伙伴/武器外观 → 穿戴与幻化 → 构筑管理 → 种族、战袍及高级统计**。每项都应保留未知数据并使用单独的游戏测试样本。

## 验证与维护

```text
node tools/build-resources.cjs
node --test tests/zones.test.cjs tests/resources.test.cjs tests/i18n.test.cjs
node tests/zones.browser.cjs <sample.sav>
```

`src/zones.js` 负责地图记录解析、变更与导出验证；界面继续通过原有统一导出入口保存。只更新英雄等级时也会计入地图修改摘要。语言切换、恢复和重新导入均保留正确职业隔离。
