# 成就点与印记测试说明

**2026-10-30 用户反馈：成就点、印记两项游戏测试均已通过。** 以下保留复测步骤；v1.6.1 新增界面语言切换。

## 已实现

打开项目 `index.html`，使用顶部“成就点 / 印记”入口。所有功能仍在单个 HTML 中，可直接离线使用。

- 展示累计获得、强化已消费和可用成就点。
- 输入目标可用点数，以增减真实成就的方式调整；不会写入游戏可能不读取的虚构点数字段。
- 逐项勾选成就；保留原有完成时间，新增成就写入当前 Unix 秒时间。
- 编辑永久强化等级，或清空强化以返还计算中的消费点数。
- 独立编辑 9 个职业的印记，支持创建原来不存在的职业记录。
- 统一导出、恢复导入值、修改摘要、无效输入拦截和原始备份。

## 样例基准

本次样例文件 `AzerothSurvivors 2026-10-29 14-02-31.sav` 计算结果：

| 项目 | 编辑器显示 |
| --- | ---: |
| 已完成成就 | 26 项 |
| 已获得成就点 | 405 |
| 永久强化已消费 | 315 |
| 可用成就点 | 90 |
| 法师印记 | 445 |
| `stat.marks` | 445，作为独立统计保留 |

点数权重与强化费用来自 2026-10-29 官方网页客户端静态数据。游戏包版本与用户本地游戏是否完全一致，仍需要以下测试确认。

## 第一轮：印记

1. 在游戏中先导出当前进度备份；测试时使用自己希望保留进度的存档。
2. 将那份存档导入编辑器，仅修改法师印记，例如 `445 → 446`。
3. 点击底部 **Export Save**，将导出文件导入游戏。
4. 检查法师印记是否为 446；切换其他职业，确认没有串改。
5. 退出重开或完成一局后再次检查数值是否保留。

反馈建议：导入后数值、完成一局后数值、有没有其他资源跟随变化。若消费一次印记后再导出一份存档，还能确认 `stat.marks` 是否确实属于累计统计。

## 第二轮：成就点

1. 使用第一轮之前的备份，避免印记变化混入这次测试。
2. 先核对游戏的已获得/可用点数与编辑器是否一致。样例暂算为 `405 / 90`，如果游戏不同，请记录两处实际数值。
3. 在编辑器将“目标可用成就点”设为 `100`，点击 **调整成就点**。页面会自动选择一组可精确凑出差值的成就；可展开“逐项编辑成就”查看结果。
4. 导出并导入游戏，检查可用点数是否为 100。
5. 尝试购买一项已解锁且买得起的强化，确认点数可消费；退出重开或完成一局后检查是否保留。

这个操作会增减成就及其关联奖励。若只想恢复消费过的点数，可以改为降低强化等级，但对应强化效果也会降低。

反馈建议：修改前点数、修改后点数、能否消费、重开后是否保留。若不一致，提供测试后的新存档即可定位奖励权重、隐藏消费或游戏重算规则。

## 数据边界

- `stat`、地图通关、装备、图鉴、宠物、`glow` 和 `pity` 不随本功能自动调整。
- 新增印记记录和点数调整标为实验性；游戏内持久化尚未验证。
- 对未知成就或强化，保留其原始数据，不把未知奖励/费用当作 0。
- 发现已购买战袍时，暂不提供完整余额与目标点数计算；逐项成就编辑仍可使用。后续补齐战袍费用表即可扩展。
- 本轮没有修改地图难度。

## 开发验证

已验证：模型测试、真实样例导入、印记与目标点数编辑、加密导出、重新导入、原始备份逐字一致、非法输入拒绝、职业隔离、恢复和移动端布局。

数据来源为官方网页客户端 WASM 的静态内存与成就构造函数，未运行其代码。目录元数据保存在 `data/resource-catalog.json`，包含来源、获取日期和 SHA-256。部分新版本或动态成就未收录，列表不代表游戏全部成就。
